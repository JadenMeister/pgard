# Changelog

All notable changes to PGARD are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project follows [Semantic Versioning](https://semver.org) with the pre-1.0 policy in [docs/RELEASING.md](docs/RELEASING.md). There is no release yet; everything merged so far is listed under Unreleased.

## [Unreleased]

### Added

- Java and Kotlin Spring Security and session configuration: `PG-CSRF-001` and `PG-COOKIE-001` now run on Java and Kotlin, and the new rule `PG-CONF-001` (OWASP A01/A02:2025, CWE-942 and CWE-862) reports a catch-all `permitAll`, `web.ignoring()` of non-static paths, wildcard CORS with credentials, `@EnableWebSecurity(debug = true)`, security debug logging and Actuator `exposure.include=*` without Spring Security. CSRF disabled is medium on a session or cookie chain (`formLogin`, `rememberMe`, `oauth2Login`, a policy that is not STATELESS, or no policy), is not reported on an explicitly STATELESS chain that uses bearer or JWT auth, and is low and `; inferred` when it cannot be told. `application*.properties` and `application*.yml` are read in Java and Kotlin projects (coverage area `source:jvm-config`; a malformed or oversized file is partial). Filter chains built by a custom configurer or a helper outside the file are partial.
- Scanning: `scan code`, `scan history`, `scan web` and `scan all` for the Git root of the current directory, with rules for JavaScript/TypeScript, React, Vue and Go, plus committed `.env` files and secrets in Git history.
- Java and Kotlin SQL injection rule `PG-SQL-005` (JDBC, Spring JdbcTemplate, JPA/Hibernate, Spring Data `@Query` SpEL, MyBatis `${}` in mapper XML and annotations); intra-procedural.
- Java and Kotlin OS command execution rule `PG-CMD-003` (`Runtime.exec`, `ProcessBuilder`, Commons Exec; shell wrappers and `exec(String)` critical, a tainted argument of a fixed program reported as argument injection) and path traversal rule `PG-PATH-002` (`File`, `Path`, `Files.*`, file streams, `getRealPath`, `ResourceLoader`; zip slip from archive entry names; canonical guards, `FilenameUtils.getName` and `getFileName()` demoted to low confidence); intra-procedural, one file at a time.
- Java and Kotlin cryptography rules on the JVM engine, extending the existing ids: `PG-CRYPTO-001` (`MessageDigest` MD5/SHA-1/SHA, Guava `Hashing.md5/sha1`, Commons Codec and Spring `DigestUtils` applied to a password-named value), `PG-CRYPTO-002` (literal keys for `SecretKeySpec`, JJWT, Auth0 `HMAC256`, Nimbus `MACSigner`, `PBEKeySpec`; a Spring `@Value("${jwt.secret:literal}")` or `getProperty(name, "literal")` default at medium confidence, "default value in source"), `PG-CRYPTO-003` (DES, RC4, bare `AES`, ECB, fixed or all-zero IV, `java.util.Random` or `Math.random()` reaching a key, IV, salt or token) and `PG-AUTH-001` (a password-named request value saved through a repository, entity manager or raw JDBC without a hash call). Pattern rules over one file; a non-literal `Cipher.getInstance` algorithm is silent unless it comes from configuration with a weak default (low). Inferred values are low confidence with `; inferred`. Bouncy Castle, Tink, Jasypt and Shiro crypto add `partial` `source:crypto:*` areas. A `@Value` default matched by name only is low confidence (medium when it reaches a key API); deprecated Spring password encoders and Shiro `setCipherKey` literals are reported; `PG-CRYPTO-003` is retitled to cover fixed IVs and predictable random values. The detection criteria version is now `2026.10-mvp.6`.
- Java and Kotlin XSS rule `PG-XSS-004` (servlet `getWriter()` / `getOutputStream()`, Ktor `respondText` with an HTML content type, `@ResponseBody` and `@RestController` String bodies, JSP `<%= %>`, `out.print`, `${param.x}` and `<c:out escapeXml="false">`, Thymeleaf `th:utext` and `[( )]` with a model value matched by name to a controller that fills it from request input; `th:text`, `<c:out>`, `fn:escapeXml` and JSON responses are not reported) and SSRF rule `PG-SSRF-002` (`URL.openConnection`/`openStream`, `HttpRequest.newBuilder`, `RestTemplate`, `WebClient`, OkHttp, Apache HttpClient, Ktor client, Jsoup; a fixed base URL with only a path or query from the request, or a host allowlist check that exits on failure, is reported at low confidence). Escaping helpers and checks demote to low confidence (`; inferred`); FreeMarker, Velocity, Pebble, Mustache and JTE templates and reflection next to these APIs make the coverage partial. Java and Kotlin now have five rule categories.
- Fix: the source walk no longer skips things silently (#332). Directories named like build output (`dist`, `build`, `out`, `coverage`, `.next`, `.nuxt`, `.output`, `.svelte-kit`, `.turbo`, `.cache`; `.git` stays silent) are reported in a new `source:build-output` coverage note (count, up to 5 paths, set fingerprint). One that directly contains source files (`.ts`, `.tsx`, `.go`, `.py`, `.php`, `.java`, `.kt`, `.kts`; not `.d.ts`) is walked as first-party code (a VS Code-like `build/*.ts`, `scripts/build/release.ts`) and counted in the note ("N skip-named directories walked because they contain source"); nested skip-named directories are probed one at a time, at most 200 directories in all. The rest, such as tsc `dist/` and `out/` with `.js`, `.d.ts` and `.map` files, are skipped and listed. Exit codes: typical repositories (a Node repository with `dist/`, `build/`, `coverage/` or `.next/` build output) are unchanged, because the area is informational (`completed`) like `source:dependency-directories`; it is `partial` (exit 4) only when something was skipped and no source file was found anywhere else. Repositories that keep first-party source directly in a `build/`, `out/` or `dist/` directory are now analyzed instead of silently skipped, so they may report findings they did not before. A directory named `build`, `out` or `dist` under a JVM source root (`src/<set>/java` or `src/<set>/kotlin`) with a Maven or Gradle manifest (`pom.xml`, `build.gradle(.kts)`, `settings.gradle(.kts)`) in any ancestor directory is a package and is walked. `pgard.config.json` has no include option, so the note says to move code out of a skipped directory. `.xml` files under `res/` or `target/` in a JVM project (`source:xml-skipped`, informational), files whose `lstat` failed (`source:unreadable-files`, `partial`) and FIFOs, sockets and devices with an analysable file name (`source:special-files`, informational) are counted too, and unreadable or over-1-MiB XML is now reported in Kotlin-only and Gradle/Maven projects, not only when Java files exist. Comparing scans: `source:unreadable-files` and `source:minified` block only when their note changes; `source:build-output` holds back a finding only when it is in such a directory (not a source file directly in one, and not under a JVM source root) and the skipped set differs between the two scans, and `source:xml-skipped` only a finding in such an XML file (the partial form of `source:build-output` follows its note); `source:special-files` never blocks. Result schema `1.3` (additive minor bump, per docs/RESULT_SCHEMA.md): the `source:build-output` coverage entry carries an optional `walkedDirectories: { paths, complete }`; comparison treats a finding below a directory walked in both scans as ordinary, so findings deeper inside a walked `build/` are not held when `coverage/` or `.next/` appears. Results without the field, or with an incomplete list, fall back to the conservative rule. Known limitations: a file moved from analyzed code into a skip-named directory shows as no longer reported (as before); source nested deeper than one level in a skip-named directory (Angular-like `packages/x/build/src/*.ts`, where `build/` itself holds no source file) is still skipped.
- Fix: a Java or Kotlin file whose only syntax errors are tree-sitter `MISSING` nodes is now counted as partial coverage, as for Python (#324).
- PHP analysis, first slice: the PHP grammar is used for `.php` and `.phtml` files (Blade `.blade.php` is detected, `source:php:blade` is `not_tested`), Laravel and Symfony are detected from `composer.json` and namespaces, SQL injection rule `PG-SQL-007` (`mysqli_query`, `->query`/`exec`/`prepare`, PDO, Laravel `DB::raw`/`DB::select`/`whereRaw`/`orderByRaw`, Doctrine `createQuery`/`executeQuery`) and OS command execution rule `PG-CMD-005` (`exec`, `system`, `shell_exec`, `passthru`, `popen`, `proc_open`, `pcntl_exec`, backticks, Symfony `Process`); intra-procedural, one file at a time. XSS, file inclusion and path, SSRF, cryptography and settings are not checked yet for PHP. Argument arrays with a fixed program report argument injection; `call_user_func('system', ...)` and a variable holding a literal function name are resolved; unresolved dynamic calls given data make the area partial. `pgard rules list --language php`.
- Python analysis, first slice: Django, Flask and FastAPI detection (imports, `requirements*.txt`, `pyproject.toml`), SQL injection rule `PG-SQL-006` (DB-API `execute`, SQLAlchemy `text()`, Django `.raw()` / `.extra()` / `RawSQL`, `pandas.read_sql`) and OS command execution rule `PG-CMD-004` (`os.system`, `os.popen`, `subprocess` with `shell=True` or a string built from data, a data-chosen program or shell script in a list, `asyncio` subprocesses, `os.exec*`); intra-procedural, with the same demote-not-drop policy and exit-or-success-branch guard rule as the Java and Kotlin rules. XSS, SSRF, path traversal, cryptography and settings checks for Python are reported as `not_tested` (`source:python:other-categories`). `rules list --language python` is new.
- Intentional change to `PG-SQL-005`: the name of an archive entry (`ZipEntry.getName()`, tar, jar, Zip4j) and the file name of an upload (`MultipartFile.getOriginalFilename()`) are now request input for the SQL rule too (they were unknown values at low confidence).
- Authorization gate: GitHub sign-in stored in the OS keychain, owner approval through the PGARD GitHub App (including a guided install and re-check), organization-owner support and the contribution check.
- Loopback dashboard (English and Korean) and redacted HTML and PDF reports, with an embedded Korean-capable PDF font.
- Output formats: `--format json` (result schema 1.1, `readScanResult`) and `--format sarif` (SARIF 2.1.0); a grouped, severity-sorted terminal result screen.
- Rule metadata: OWASP Top 10 2025, CWE Top 25 and CERT Java mappings, rationale and remediation, rule statistics and a standards coverage map; Korean or English rule text.
- Tree-sitter based analysis foundation, lockfile parsing and a user-run OSV data download (`pgard advisories update`).
- Project configuration file `pgard.config.json`, suppressions and baselines, a local result store with retention and history clearing, and comparison with the previous scan.
- Windows support; an accuracy corpus with precision and recall checked in CI.
- Single installable npm package `pgard` built with `npm run pack:pgard` and checked by `npm run smoke:pack`; release workflow, Homebrew formula template and release procedure (nothing published yet).
- Guided first run for the interactive menu: with no saved sign-in it offers to sign in, then, when the PGARD GitHub App is the only thing missing, shows the install link, waits for Enter and re-runs all five authorization checks (at most 3 retries), then scans. Other blocked reasons are shown as before with no retry loop. The authorization gate is unchanged (nothing cached, nothing skipped). English and Korean text.
- Docs: [TUI approach evaluation](docs/TUI_EVALUATION.md) for the M6 CLI dashboard (no code change).
- Panel view, Findings panel: keyboard navigation, filters and finding details. `Enter` opens the selected finding (redacted evidence, fix, OWASP/CWE/CERT links) and `Enter` or Esc closes it; `1` to `5` and `s` filter by severity, `a` by area, `r` by rule, `c` clears the filters, and `/` searches title, rule id and path (Esc clears the search, the next Esc leaves). A line above the list always shows `N of M` and the active filters. The footer and the `?` help list the keys in English and Korean. Exit codes, terminal restore and resize handling are unchanged.
- Panel view, Trend panel (between Coverage and Findings in the Tab order): this repository's stored scans from the local result store only (up to 20, newest first), the latest scan against the previous one (new, no longer reported, unchanged) and severity totals per scan as a stacked bar with a different character per severity (colour is never the only signal), scan dates with relative labels, and a plain text table at 60 columns or fewer. "No history yet" states for a single scan, `--no-store` / `PGARD_NO_STORE`, and an unreadable store (short reason, never a crash). English and Korean; the tab bar now scrolls with `<` and `>` instead of collapsing to one tab when it does not fit. Exit codes, the width rules, restore paths and `PGARD_PANELS` are unchanged.
- Coverage: minified bundles (`*.min.js`, `*.min.mjs`, `*.min.cjs`) were skipped without a trace. They now appear as a `partial` `source:minified` coverage area (count, up to 5 paths, reason "minified bundle, not analyzed"; no entry when none were skipped), so a project that ships minified code is no longer reported as fully scanned. Scans of projects that contain `*.min.js` files now end `partial` (exit code 4) and limit standards coverage to `rules_partial`; add an `exclude` pattern to `pgard.config.json` for the bundles to clear it. In a comparison with the previous scan the area blocks only when the set of skipped bundles changed. Closes #297.

### Changed

- `pgard scan` in a terminal now prints the findings first and the summary last, so the screen ends on the status line, the charts, the coverage count (partial and not-tested areas named) and a "Next" line. Findings are compact by default: critical and high first, at most 10 groups of one or two lines, then `+N more (medium 17, low 2)` pointing to `--all-findings`; test, fixture and vendored code get a title line with counts by severity and keep their critical and high groups (and every secret) listed; the rest is counted. Evidence, fix and standards appear with `--all-findings` (the previous full detail), in the panel view, the dashboard and reports. Long lines are wrapped to the terminal width with a hanging indent, by character and keeping colours per piece; only PGARD's own standards links may run past the width, and other URLs are cut at twice the width. Output that is not a terminal (pipes, files, CI), `--format json` and `--format sarif` are unchanged. Partial and not-tested coverage and the "not a safe result" warnings are shown in the compact form too.
- The panel view now opens by itself for `pgard scan` in a terminal, as the menu already did. `PGARD_PANELS=off` (also `0`, `false`, `no`) turns it off, `--panels` still forces it, and it never opens without a terminal or with `--format json` or `sarif`. The text result is printed before it opens and stays on the main screen. It does not open by itself when `CI` is set (other than empty, `0`, `false`), under `GITHUB_ACTIONS`, `BUILDKITE`, `TF_BUILD` or `JENKINS_URL`, with `TERM=dumb`, or for `pgard baseline set --from-current`; `--panels` or `PGARD_PANELS=on` still open it. Set `PGARD_PANELS=off` when you run `pgard scan` under `script`, `expect`, VS Code tasks or `docker run -it`, where a pseudo-terminal exists but nobody presses a key. Ctrl+D and a closed terminal now leave the view like Esc.
- The result and report text is localized in Korean and English (CLI, reports, dashboard).
- Rule rationale and remediation texts and mappings were rewritten against OWASP 2025 and concrete attack and fix examples.
- Requires Node.js 22.23.4, 24.22.1 or 26.12.1, or a newer patch on the same line; `pgard doctor` fails older releases.
- Analysis is code-based: a scan does not check dependencies against an advisory database. The only OSV use is the user-run `pgard advisories update` download.

### Fixed

- Without a terminal (stdin or stderr not a TTY) and without a usable saved sign-in, `scan` (all forms and formats), `baseline` and `project verify` no longer start the GitHub device flow and wait up to 15 minutes: they exit 3 at once with a blocked result ("Not signed in ... Run `pgard login` in a terminal first"), valid JSON or SARIF for those formats. `pgard login` without a terminal is a usage error (exit 2). Interactive behaviour is unchanged (#296).
- The keychain sentence "the OS keychain could not be used ..." is now translated in Korean output (#300, part).
- Many false negatives and false positives in secret, auth, cookie and CSRF detection and in Git history checks.
- Port-discovery and dashboard port-gate races, keychain sign-in races, and layout at narrow widths.
- Install guidance for private repositories outside the App installation and for a 404 when the App already covers all repositories.

### Security

- Dashboard and web checks are loopback-only; reports and results are redacted, and the dashboard gates port discovery on the full authorization outcome.
- Packaged grammars are checksum-pinned and verified; the package has no install scripts and only exact-pinned direct dependencies.
