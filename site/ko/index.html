내 프로젝트의 보안 스캐너 — 코드, Git 이력, 로컬 웹을 내 컴퓨터에서 점검합니다.

GitHub에서 Star 스타 시작하기

설치

$ npm install -g pgard

첫 릴리스 준비 중 — 지금은 소스에서 빌드하세요

$ git clone https://github.com/JadenMeister/pgard.git && cd pgard && npm ci && npm run build

검사 권한이 있는 GitHub 저장소만 검사하며, 검사할 때마다 이를 다시 확인하고, 코드와 결과를 업로드하지 않습니다. 하지 못하는 일

pgard scan --panels --lang ko — 터미널의 읽기 전용 전체 화면 (테스트 예시, 60x20)

검사 결과와 패널 보기: 가상 프로젝트의 테스트 스냅숏 예시 데이터이며 ...로 줄였고, 실제 검사 결과가 아닙니다. 도움말과 규칙 목록: 빌드한 CLI의 실제 출력(영어 원문).

시작하기. 세 단계면 됩니다.

  1. 소스에서 빌드설치

    Node.js 22.23.4, 24.22.1 또는 26.12.1(또는 더 새로운 패치)과 Git이 필요합니다. 두 번째 줄은 pgard를 PATH에 올립니다.

    Node.js 22.23.4, 24.22.1 또는 26.12.1(또는 더 새로운 패치)과 Git이 필요합니다. Homebrew로도 설치할 수 있습니다.

    $ git clone https://github.com/JadenMeister/pgard.git && cd pgard && npm ci && npm run build
    $ npm link -w @pgard/cli
    $ npm install -g pgard

  2. 로그인과 승인

    GitHub에 한 번 로그인합니다(OS 키체인에 저장). owner가 PGARD GitHub App을 설치해야 하며, 없으면 PGARD가 링크를 알려 줍니다.

    $ pgard login

  3. 검사

    프로젝트 루트에서 실행합니다. 권한을 다시 확인하고, 터미널에서는 완료 또는 부분 완료된 검사의 텍스트 결과 뒤에 패널 보기가 열립니다(CI나 PGARD_PANELS=off에서는 제외).

    $ pgard scan
다른 설치 방법: npm, Homebrew

npm과 Homebrew는 첫 릴리스와 함께 제공됩니다. 그 전에는 npm install -g pgard가 pgard 명령이 없는 자리표시 패키지만 설치하며, Homebrew tap도 아직 없습니다.

$ npm install -g pgard$ brew install jadenmeister/pgard/pgard
$ brew tap jadenmeister/pgard$ brew install pgard

pgard doctor는 실행 환경을 진단합니다(권한 확인은 아닙니다). npm link를 하지 않았다면 클론한 폴더에서 node apps/cli/dist/bin/pgard.js를 실행하세요. 모든 명령과 옵션은 README에 있습니다.

무엇을 검사하나. 세 영역 중에서 검사마다 고릅니다.

모든 결과는 어디까지 검사했는지 알려 줍니다. 전체 규칙 목록은 pgard rules list로 볼 수 있습니다.

code

  • SQL 인젝션, XSS, SSRF
  • OS 명령 실행, 경로 조작(path traversal)
  • 취약하거나 코드에 박힌 암호화 키, 해시하지 않은 비밀번호
  • 쿠키 플래그, CSRF, 로그인 경로의 요청 횟수 제한 부재

범위 커밋하지 않은 파일을 포함한 현재 파일. 빌드 산출물과 의존성은 건너뛰고 목록을 알려 줍니다.

history

  • 커밋된 .env 파일
  • 추적 중인 파일의 시크릿
  • 이력에만 남은 시크릿

범위 시크릿 값은 모든 출력에서 가려집니다.

web

  • 보안 헤더, 쿠키 플래그
  • 자격 증명을 허용하는 CORS
  • 버전 노출, 디렉터리 목록
  • 노출된 /.env와 /.git

범위 사용자가 확인한 127.0.0.1의 서비스만. 익명 GET과 HEAD, 페이지 20개, 깊이 2, 전체 60초.

권한 확인 방식. 검사 전에 매번 다섯 가지를 확인합니다.

검사 도구는 남의 코드를 들여다보는 데도 쓸 수 있어서, CLI든 대시보드든 모든 검사는 먼저 다섯 가지를 확인합니다. 재사용하는 것은 로그인뿐이고 건너뛸 수 없습니다. 근거가 없으면 검사를 막고(종료 코드 3) 실패한 확인을 알려 줍니다.

  1. 저장소github.com 원격이 하나인 Git 루트.
  2. GitHub 신원한 번 로그인하면 OS 키체인에 저장됩니다.
  3. Owner 승인owner가 PGARD GitHub App을 설치했어야 하며, 조직이라면 내가 조직 owner여야 합니다.
  4. 현재 접근 권한지금 읽기 권한이 있어야 합니다.
  5. 기여owner는 기본 브랜치와 이력을 공유해야 하고, 그 외에는 그곳에 병합된 풀 리퀘스트나 검증된 서명 커밋이 필요합니다.
GitHub App에 대해

owner 계정에 앱을 설치하는 것이 곧 owner의 승인이며, PGARD가 대신 설치할 수는 없습니다. 앱에는 공개 client id가 내장되어 있고 client secret은 없습니다. 설치만 빠져 있다면 설치 링크를 출력하고 최대 10분 동안 기다린 뒤 다섯 가지 확인을 처음부터 다시 합니다. pgard project verify는 검사 없이 확인만 실행합니다.

남는 것과 나가는 것. 코드와 결과는 내 컴퓨터에 남습니다.

내 컴퓨터에 머무는 것

  • 소스 코드, Git 이력, 검사 결과
  • 저장소별 최근 결과 20회, 90일간. --no-store로 끕니다
  • GitHub 로그인은 OS 키체인에 저장되며 파일에는 쓰지 않습니다
  • 내보낸 보고서는 사용자가 고른 위치에만

네트워크로 나가는 것

  • GitHub: 로그인과 권한 확인 메타데이터, 저장소 소유자/이름과 로컬 커밋 SHA 포함
  • OSV 공개 데이터(내려받기만 하고 아무것도 보내지 않음): 사용자가 pgard advisories update를 실행할 때만
  • 루프백: 로컬 포트마다 GET / 한 번
자세히

저장된 결과는 macOS·Linux에서 소유자만 읽을 수 있습니다. 권한 확인 메타데이터는 신원, 앱 설치 여부, 조직 멤버십, 접근 권한, 기여 내역입니다. 루프백 GET은 권한 확인이 통과한 뒤에만 보냅니다. 저장된 결과는 pgard history clear --all로 지웁니다. OSV 내려받기는 공개 취약점 데이터입니다. 루프백 GET은 사용자가 포트를 확인하기 전에 각 로컬 포트의 정체를 보여 주기 위한 것입니다.

이 웹사이트는 정적 페이지입니다. 아무것도 검사하지 않고 데이터를 수집하지 않으며 로그인이나 업로드 기능이 없습니다. 대시보드도 아닙니다. 대시보드는 사용자 컴퓨터에서 실행됩니다.

한계. 하지 못하는 일.

  • 검사 범위부분 검사는 그대로 표시하고 종료 코드 4로 끝납니다.
  • 언어Java와 Kotlin은 일곱 분류, Python과 PHP는 두 분류만.
  • 의존성npm과 Go만, 직접 내려받은 OSV 데이터와 버전 범위로 대조합니다.
  • 원격사용자가 확인한 127.0.0.1 서비스만. 로그인 상태 탐색과 상태를 바꾸는 요청은 하지 않습니다.
  • 신호패턴 기반이라, 발견 없음이 안전을 뜻하지 않습니다.
  • 정확도코퍼스가 작고(규칙당 약 10개) 개발자가 직접 썼습니다.

FAQ. 자주 묻는 질문.

내 코드가 내 컴퓨터를 벗어나나요?

아니요. 코드, Git 이력, 결과는 사용자 컴퓨터에서 처리되며 업로드되지 않습니다. 네트워크로 나가는 것의 전체 목록은 위에 있습니다.

왜 GitHub 로그인이 필요한가요?

검사 권한을 증명하기 위해서입니다. 신원, owner의 앱 설치, 현재 접근 권한, 저장소 소유 또는 기여를 확인합니다. 토큰은 OS 키체인에 저장되며 파일에는 저장되지 않습니다.

어떤 저장소를 검사할 수 있나요?

내 저장소는 내 계정에 PGARD GitHub App을 설치한 뒤에 가능합니다(PGARD가 안내합니다). 다른 사람의 개인 저장소는 owner가 앱을 설치했고, 내게 현재 읽기 접근 권한이 있으며, 기본 브랜치에 병합된 풀 리퀘스트 또는 검증된 서명 커밋이 있을 때만 가능합니다. 조직 저장소는 내가 조직의 활성 owner이고 앱이 해당 저장소에 설치되어 있을 때만 가능합니다. 원격 저장소는 검사하지 않으며, 대상은 항상 현재 디렉터리의 Git 루트입니다.

결과가 깨끗하면 안전하다는 증거인가요?

아니요. 모든 결과에는 검사하지 못한 부분이 나오고, 표준 매핑 현황은 한 분류의 약점 중 규칙이 있는 것이 얼마나 적은지 보여 줍니다. 한계를 참고하세요.

Windows에서도 동작하나요?

네. macOS, Linux, Windows를 지원하며 CI가 세 환경에서 전체 테스트를 실행합니다. Windows에서는 로그인이 자격 증명 관리자에 저장됩니다. 예전 콘솔 창(legacy conhost)과 화면 표시(글꼴, 색, 문자)는 사용자가 직접 확인한 적이 없습니다.

CI에서 쓸 수 있나요?

지금은 어렵습니다. 모든 검사에는 CI 러너에 없는 GitHub 로그인이 필요해서, 러너에서는 차단된 결과만 나옵니다. 로컬에서 PGARD를 실행하고 --format json 또는 --format sarif 출력과 종료 코드(0 완료, 3 차단, 4 부분 완료)를 직접 만든 스크립트에서 사용하세요.

더 많은 질문

호스팅형 스캐너와 무엇이 다른가요?

코드가 어떤 서비스로도 복사되지 않습니다. 대신 직접 실행해야 하고, 호스팅된 대시보드나 상시 모니터링은 없으며, 검사해도 되는지 GitHub에 확인합니다.

PGARD의 취약점은 어떻게 제보하나요?

공개 이슈가 아니라 비공개로, 저장소 Security 탭의 Report a vulnerability 버튼으로 제보해 주세요. 범위는 보안 정책을 참고하세요. 현상금은 없습니다.
