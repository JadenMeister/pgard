내가 권한을 가진 저장소의 보안 검사, 내 컴퓨터에서.

PGARD는 검사 권한이 있는 GitHub 프로젝트를 위한 로컬 보안 검사 도구입니다. 현재 코드와 설정, Git 이력, 그리고 원하면 127.0.0.1에서 실행 중인 웹 서비스를 검사합니다. 코드와 결과는 사용자 컴퓨터를 벗어나지 않습니다.

설치

$ npm install -g pgard

사전 출시 첫 릴리스 준비 중입니다. 지금은 소스에서 빌드해 사용하세요.

$ git clone https://github.com/JadenMeister/pgard.git && cd pgard && npm ci && npm run build

GitHub에서 보기 문서 읽기 하지 못하는 일

  • 3검사 영역: 코드, Git 이력, 내 로컬 웹 서비스
  • 38현재 규칙 목록의 규칙 수
  • 5검사할 때마다 하는 권한 확인

01

직접 보기.

이 저장소를 빌드해서 얻은 실제 출력입니다. 보기를 골라 보세요.

pgard scan --panels --lang ko — 읽기 전용 전체 화면 (테스트 예시, 60x20)

도움말과 규칙 목록은 빌드한 CLI의 실제 출력입니다(오프라인, 로그인 없음, 영어 원문). 검사 결과와 패널 보기는 저장소의 테스트 스냅숏에서 가져온 것으로, 가상의 프로젝트에 대한 예시 데이터이며 일부는 ...로 줄였습니다. 실제 저장소를 검사한 결과가 아닙니다.

02

무엇을 검사하나.

검사할 때마다 세 영역 중에서 고릅니다. 결과에는 무엇을 검사했고 무엇을 검사하지 못했는지가 함께 나옵니다.

code

코드

현재 소스 코드와 설정입니다.

  • SQL 인젝션, XSS, SSRF, OS 명령 실행, 경로 조작(path traversal)
  • 취약하거나 코드에 박힌 암호화 키, 해시하지 않은 비밀번호, 쿠키 플래그, CSRF, 로그인 경로의 요청 횟수 제한 부재
  • 작업 트리를 훑으며, 빌드 산출물과 의존성 디렉터리는 건너뛰고 그 목록을 알려 줍니다

history

Git 이력

커밋된 시크릿을 과거부터 현재까지 찾습니다.

  • 커밋된 .env 파일
  • 추적 중인 파일의 시크릿, 그리고 이력에만 남은 시크릿
  • 시크릿 값은 모든 출력에서 가려집니다

web

내 로컬 웹 서비스

사용자가 127.0.0.1에서 실행 중인 서비스만, 직접 확인한 뒤에만 검사합니다.

  • 익명 GET과 HEAD 요청만 보내며 폼 제출은 하지 않습니다
  • 보안 헤더, 쿠키 플래그, 자격 증명을 허용하는 CORS, 버전 노출, 디렉터리 목록, 노출된 /.env와 /.git
  • 한도: 페이지 20개, 깊이 2, 요청당 5초, 전체 60초

언어와 검사 분류

언어마다 실행되는 규칙이 다릅니다. pgard rules list의 내용을 따랐습니다.

언어 분류
JavaScript, TypeScript SQL 인젝션, XSS, SSRF, 명령 실행, 경로 조작, 암호화, 비밀번호 저장, 쿠키, CSRF, 요청 횟수 제한
React, Vue dangerouslySetInnerHTML과 v-html의 XSS, 그리고 JavaScript/TypeScript 규칙
Go SQL 인젝션(database/sql, GORM), 명령 실행, 경로 조작, SSRF, 암호화, 쿠키
Java, Kotlin 세 가지 분류만 검사합니다: SQL 인젝션, 명령 실행, 경로 조작(MyBatis 매퍼 XML 포함). 그 밖의 분류는 아직 검사하지 않습니다.
Python, PHP 파일은 인식하지만 아직 분석하지 않습니다. 검사 범위에는 미검사으로 표시됩니다.

03

권한 확인이 먼저.

PGARD는 사용자에게 검사 권한이 있다는 근거가 있을 때만 저장소를 검사합니다.

검사할 때마다 CLI와 대시보드에서 다섯 가지 확인을 처음부터 다시 합니다. 건너뛰는 옵션도, 이전 승인을 재사용하는 일도 없습니다. 근거가 없거나 불분명하면 검사를 막고(종료 코드 3) 어떤 확인이 왜 실패했는지 알려 줍니다.

  1. 저장소현재 디렉터리가 올바른 이력을 가진 Git 저장소 루트이고, github.com 원격이 하나로 분명해야 합니다.
  2. GitHub 신원GitHub 디바이스 플로우로 로그인하거나, OS 키체인에 저장된 로그인을 재사용합니다.
  3. Owner 승인저장소 owner가 PGARD GitHub App을 설치했어야 합니다. 조직 저장소라면 사용자가 조직의 활성 owner여야 합니다.
  4. 현재 접근 권한지금 최소한 읽기 권한이 있다고 GitHub가 알려 주어야 합니다.
  5. 기여owner는 기여를 따로 증명하지 않아도 되지만, 로컬 이력이 기본 브랜치와 커밋을 공유해야 합니다. 그 외의 사용자는 병합된 풀 리퀘스트 또는 검증된 서명 커밋이 필요합니다.

왜 이렇게 하나.

PGARD는 자기 프로젝트를 점검하는 사람을 위한 도구입니다. 보안 검사 도구는 남의 코드를 들여다보는 데도 쓸 수 있으므로, 사용자와 owner의 승인에 연결할 수 없는 대상은 매번 검사하지 않습니다. 막힌 경우에는 해결 방법을 안내합니다.

GitHub App.

로그인은 디바이스 플로우로 PGARD GitHub App을 통해 이루어집니다. 앱에는 공개 client id가 내장되어 있고 PGARD에는 client secret이 없습니다. owner 계정에 앱을 설치하는 것이 곧 owner의 승인이며, PGARD가 대신 설치할 수는 없습니다. 설치만 빠져 있다면 설치 링크를 출력하고 최대 10분 동안 기다린 뒤 다섯 가지 확인을 처음부터 다시 합니다.

04

로컬 우선.

코드, 이력, 결과는 사용자 컴퓨터에서 처리됩니다.

내 컴퓨터에 머무는 것

  • 소스 코드, Git 이력, 검사 결과
  • 저장된 결과: 저장소별 최근 20회, 90일, macOS·Linux에서는 소유자만 읽을 수 있는 권한. --no-store로 끌 수 있고 pgard history clear --all로 지웁니다
  • GitHub 로그인은 OS 키체인에 저장되며 파일에 쓰거나 출력하지 않습니다
  • 내보낸 보고서는 사용자가 고른 위치에만 저장됩니다

네트워크로 나가는 것

  • 검사 중 GitHub: 로그인과 권한 확인에 필요한 메타데이터(신원, 앱 설치 여부, 조직 멤버십, 접근 권한, 기여 내역). 기여를 확인하려고 로컬 커밋의 SHA를 보냅니다
  • OSV 내보내기 호스트: 사용자가 직접 pgard advisories update를 실행할 때만, 공개 취약점 데이터를 내려받습니다. 업로드하는 것은 없습니다
  • 루프백에 한정: 권한 확인이 통과한 뒤 발견된 각 로컬 포트에 GET / 한 번씩, 서비스 정체를 보여 주기 위해

이 웹사이트(pgard.dev)는 정적 페이지일 뿐입니다. 아무것도 검사하지 않고, 데이터를 수집하지 않으며, 로그인이나 업로드 기능이 없고, 트래커, 분석 도구, 쿠키, 외부 글꼴, CDN도 없습니다. 이 사이트는 대시보드가 아닙니다. 대시보드는 사용자 컴퓨터에서 실행됩니다.

05

솔직한 한계.

짧고 솔직하게. PGARD는 사전 출시 버전입니다.

  • 부분 검사는 숨기지 않고 보여 줍니다. 영역마다 완료, 부분 완료, 미검사, 선택 안 함으로 표시되고 부분 검사는 종료 코드 4로 끝납니다.
  • Python과 PHP는 아직 분석하지 않습니다. Java와 Kotlin은 세 분류만 검사하므로, Java 결과가 깨끗해도 XSS, SSRF, 암호화에 대해서는 아무것도 알 수 없습니다.
  • 의존성 취약점 대조는 아직 없습니다. PGARD는 취약점 데이터베이스를 포함하지 않으며, 사용자가 직접 실행하는 OSV 내려받기는 그 준비 단계입니다.
  • 원격 검사는 없습니다. 사용자가 확인한 127.0.0.1의 서비스만 검사하며, 로그인 상태의 탐색이나 공격성 요청, 상태를 바꾸는 요청은 하지 않습니다.
  • 발견 항목은 증거가 아니라 신호입니다. 탐지는 패턴 기반이라 완전하지 않고, 발견 없음이 안전을 뜻하지 않습니다. 잘못 만든 앱은 GET 요청으로도 상태가 바뀔 수 있습니다.
  • 정확도 검증용 코퍼스는 작고(규칙당 샘플 약 10개) 개발자가 직접 썼습니다. 그 점수가 사용자의 코드에 대한 약속은 아닙니다.

06

설치.

Node.js 22.23.4, 24.22.1 또는 26.12.1(또는 더 새로운 패치), Git, macOS·Linux·Windows.

사전 출시 첫 릴리스 준비 중입니다. 지금은 소스에서 빌드해 사용하세요.

npm아직 배포 전사용 가능

$ npm install -g pgard
$ npx pgard doctor

첫 릴리스 전에는 npm install -g pgard가 pgard 명령이 없는 자리표시 패키지만 설치합니다.

Homebrew아직 배포 전사용 가능

$ brew tap jadenmeister/pgard$ brew install pgard

한 줄로도 가능: brew install jadenmeister/pgard/pgard

tap은 첫 릴리스와 함께 만들어집니다.

소스에서 빌드지금 가능

$ git clone https://github.com/JadenMeister/pgard.git$ cd pgard$ npm ci$ npm run build

선택: npm link -w @pgard/cli 로 pgard를 PATH에 올릴 수 있습니다. 아니면 node apps/cli/dist/bin/pgard.js 를 실행하세요.

처음 실행

검사할 프로젝트의 루트에서 실행하세요.

$ pgard doctor$ pgard login$ pgard project verify$ pgard scan
