남보다 먼저, 내 코드를 검사하세요.

내 프로젝트의 보안 스캐너 — 코드, Git 이력, 로컬 웹을 내 컴퓨터에서 점검합니다.

검사 권한이 있는 GitHub 저장소만 검사하며, 검사할 때마다 이를 다시 확인하고, 코드와 결과를 업로드하지 않습니다.

설치

$ npm install -g pgard

첫 릴리스 준비 중 — 지금은 소스에서 빌드하세요

$ git clone https://github.com/JadenMeister/pgard.git && cd pgard && npm ci && npm run build
GitHub에서 Star 스타 문서 하지 못하는 일

pgard scan --panels --lang ko — 터미널의 읽기 전용 전체 화면 (테스트 예시, 60x20)

도움말과 규칙 목록은 빌드한 CLI의 실제 출력입니다(오프라인, 로그인 없음, 영어 원문). 검사 결과와 패널 보기는 저장소의 테스트 스냅숏으로, 가상의 프로젝트에 대한 예시 데이터이며 표시한 곳은 ...로 줄였습니다. 실제 저장소를 검사한 결과가 아닙니다.

무엇을 검사하나

세 영역 중에서 검사마다 고릅니다. 모든 결과는 무엇을 검사했고 무엇을 검사하지 못했는지 영역마다 완료, 부분 완료, 미검사, 선택 안 함으로 알려 줍니다. 전체 규칙 목록은 pgard rules list로 볼 수 있습니다.

영역 찾는 것 범위
code SQL 인젝션, XSS, SSRF, OS 명령 실행, 경로 조작(path traversal); 취약하거나 코드에 박힌 암호화 키, 해시하지 않은 비밀번호, 쿠키 플래그, CSRF, 로그인 경로의 요청 횟수 제한 부재 커밋하지 않은 파일을 포함한 현재 파일과 설정. 빌드 산출물과 의존성 디렉터리는 건너뛰고 그 목록을 알려 줍니다.
history 커밋된 .env 파일, 추적 중인 파일의 시크릿, 이력에만 남은 시크릿 시크릿 값은 모든 출력에서 가려집니다.
web 보안 헤더, 쿠키 플래그, 자격 증명을 허용하는 CORS, 버전 노출, 디렉터리 목록, 노출된 /.env와 /.git 사용자가 확인한 127.0.0.1의 서비스만. 익명 GET과 HEAD만, 폼 제출 없음. 페이지 20개, 깊이 2, 요청당 5초, 전체 60초.

출력

terminal 영역별 검사 범위가 담긴 결과. --panels는 읽기 전용 전체 화면(개요, 차트, 검사 범위, 발견 항목)을 엽니다.
dashboard pgard dashboard는 세션 토큰을 쓰는 로컬 웹 대시보드를 127.0.0.1에서 엽니다. 어디에도 호스팅되지 않습니다.
json --format json은 가려 처리된 결과만 표준 출력으로 내보내고 진행 상황은 표준 오류로 보냅니다. 스키마는 문서화되어 있고 버전이 있습니다.
sarif --format sarif는 SARIF 2.1.0을 출력합니다. 로컬 검사가 종료 코드 0으로 끝난 뒤 GitHub 코드 스캐닝에 직접 올리세요(README의 명령). 종료 코드 3, 4, 5일 때는 올리지 마세요. 부분 검사 결과를 올리면 검사하지 않은 영역의 경고가 닫힐 수 있습니다.
html, pdf --report both --output-dir ./reports는 가려 처리된 보고서를 사용자가 고른 기존 폴더에 저장하며 기존 파일을 덮어쓰지 않습니다.
baseline pgard baseline set으로 검사 하나를 기준선으로 두면 이후 검사에서 일치하는 항목이 “기준선에 있음”으로 분류되어 새 항목이 눈에 띕니다.
incremental 다시 검사할 때는 바뀐 부분만 읽고 그 사실을 알려 줍니다. --full은 전체를 다시 검사합니다.
standards 규칙은 OWASP Top 10 2025, CWE Top 25 2025, 해당하는 경우 SEI CERT Java에 매핑됩니다. 매핑 현황은 규칙 실행됨, 일부 실행, 실행 안 됨, 규칙 없음으로만 표시하며 안전하다고 말하지 않습니다.
language 규칙 설명, 결과 화면, 보고서 제목은 한국어 또는 영어. 검사 근거, 커버리지 설명, 권한 확인 사유는 영어로 유지됩니다.

권한 확인 방식

보안 검사 도구는 남의 코드를 들여다보는 데도 쓸 수 있습니다. 그래서 PGARD는 검사할 때마다, CLI에서도 대시보드에서도, 다섯 가지 확인을 다시 합니다. 재사용하는 것은 GitHub 로그인뿐이며, 건너뛰는 옵션도 이전 승인을 재사용하는 일도 없습니다. 근거가 없거나 불분명하면 검사를 막고(종료 코드 3) 어떤 확인이 실패했는지와 그 이유를 알려 줍니다.

  1. 저장소현재 디렉터리가 올바른 이력을 가진 Git 저장소 루트이고, github.com 원격이 하나로 분명해야 합니다.
  2. GitHub 신원디바이스 플로우로 한 번 로그인하며, 로그인은 OS 키체인에 저장됩니다.
  3. Owner 승인owner가 PGARD GitHub App을 설치했어야 합니다. 조직 저장소라면 사용자가 조직의 활성 owner여야 합니다.
  4. 현재 접근 권한지금 최소한 읽기 권한이 있다고 GitHub가 알려 주어야 합니다.
  5. 기여owner는 면제되지만 로컬 이력이 기본 브랜치와 커밋을 공유해야 합니다. 그 외의 사용자는 기본 브랜치에 병합된 풀 리퀘스트 또는 검증된 서명 커밋이 필요합니다.

owner 계정에 앱을 설치하는 것이 곧 owner의 승인이며, PGARD가 대신 설치할 수는 없습니다. 앱에는 공개 client id가 내장되어 있고 client secret은 없습니다. 설치만 빠져 있다면 설치 링크를 출력하고 최대 10분 동안 기다린 뒤 다섯 가지 확인을 처음부터 다시 합니다.

$ pgard login$ pgard project verify$ pgard scan

남는 것과 나가는 것

내 컴퓨터에 머무는 것

  • 소스 코드, Git 이력, 검사 결과
  • 저장된 결과: 저장소별 최근 20회, 90일, macOS·Linux에서는 소유자만 읽을 수 있는 권한. --no-store로 끄고 pgard history clear --all로 지웁니다
  • GitHub 로그인은 OS 키체인에 저장되며 파일에 쓰거나 출력하지 않습니다
  • 내보낸 보고서는 사용자가 고른 위치에만 저장됩니다

네트워크로 나가는 것

  • 검사 중 GitHub: 로그인과 권한 확인에 필요한 메타데이터(신원, 앱 설치 여부, 조직 멤버십, 접근 권한, 기여 내역). 기여 확인을 위한 로컬 커밋의 SHA 포함
  • OSV 내보내기 호스트: 사용자가 직접 pgard advisories update를 실행할 때만, 공개 취약점 데이터를 내려받습니다. 업로드하는 것은 없습니다
  • 루프백에 한정: 권한 확인이 통과한 뒤 각 로컬 포트에 GET / 한 번씩, 서비스 정체를 보여 주기 위해

이 웹사이트는 정적 페이지입니다. 아무것도 검사하지 않고 데이터를 수집하지 않으며 로그인이나 업로드 기능이 없습니다. 대시보드도 아닙니다. 대시보드는 사용자 컴퓨터에서 실행됩니다.

한계

  • 검사 범위부분 검사는 숨기지 않고 보여 주며, 부분 검사는 종료 코드 4로 끝납니다.
  • 언어Python과 PHP는 아직 분석하지 않습니다. Java와 Kotlin은 세 분류만 검사하므로, Java 결과가 깨끗해도 XSS, SSRF, 암호화에 대해서는 알 수 없습니다.
  • 의존성알려진 취약점(CVE, OSV) 대조는 아직 없습니다. PGARD는 취약점 데이터베이스를 포함하지 않으며, 락 파일 읽기와 사용자가 직접 실행하는 OSV 내려받기는 그 준비 단계입니다.
  • 원격사용자가 확인한 127.0.0.1의 서비스만 검사합니다. 로그인 상태의 탐색, 공격성 요청, 상태를 바꾸는 요청은 하지 않습니다.
  • 신호탐지는 패턴 기반이라 완전하지 않고, 발견 없음이 안전을 뜻하지 않습니다. 잘못 만든 앱은 GET 요청으로도 상태가 바뀔 수 있습니다.
  • 정확도정확도 검증용 코퍼스는 작고(규칙당 샘플 약 10개) 개발자가 직접 썼습니다. 그 점수가 사용자의 코드에 대한 약속은 아닙니다.

다음 주제(일정 없음): 더 많은 언어와 분류, 의존성과 취약점 권고 대조, pre-commit 검사. 열린 이슈

설치

Node.js 22.23.4, 24.22.1 또는 26.12.1(또는 더 새로운 패치)과 Git이 필요하며, macOS·Linux·Windows에서 동작합니다.

첫 릴리스 준비 중입니다. 지금은 소스에서 빌드하세요.

소스에서 빌드지금 가능

$ git clone https://github.com/JadenMeister/pgard.git$ cd pgard$ npm ci$ npm run build

선택: npm link -w @pgard/cli로 pgard를 PATH에 올릴 수 있습니다. 아니면 node apps/cli/dist/bin/pgard.js를 실행하세요.

npm아직 배포 전사용 가능

$ npm install -g pgard
$ npx pgard doctor
$ npm install -g pgard$ npx pgard doctor

참고용이라 복사할 수 없습니다. 첫 릴리스 전에는 npm install -g pgard가 pgard 명령이 없는 자리표시 패키지만 설치합니다.

Homebrew아직 배포 전사용 가능

$ brew tap jadenmeister/pgard$ brew install pgard
$ brew tap jadenmeister/pgard$ brew install pgard

한 줄로도 가능: brew install jadenmeister/pgard/pgard. tap은 첫 릴리스와 함께 만들어집니다.

처음 실행 (검사할 프로젝트의 루트에서)

$ pgard doctor$ pgard login$ pgard project verify$ pgard scan

FAQ

내 코드가 내 컴퓨터를 벗어나나요?

아니요. 코드, Git 이력, 결과는 사용자 컴퓨터에서 처리되며 업로드되지 않습니다. 네트워크로 나가는 것의 전체 목록은 위에 있습니다.

왜 GitHub 로그인이 필요한가요?

검사 권한을 증명하기 위해서입니다. 신원, owner의 앱 설치, 현재 접근 권한, 저장소 소유 또는 기여를 확인합니다. 토큰은 OS 키체인에 저장되며 파일에는 저장되지 않습니다.

어떤 저장소를 검사할 수 있나요?

내 저장소는 내 계정에 PGARD GitHub App을 설치한 뒤에 가능합니다(PGARD가 안내합니다). 다른 사람의 개인 저장소는 owner가 앱을 설치했고, 내게 현재 읽기 접근 권한이 있으며, 기본 브랜치에 병합된 풀 리퀘스트 또는 검증된 서명 커밋이 있을 때만 가능합니다. 조직 저장소는 내가 조직의 활성 owner이고 앱이 해당 저장소에 설치되어 있을 때만 가능합니다. 원격 저장소는 검사하지 않으며, 대상은 항상 현재 디렉터리의 Git 루트입니다.

결과가 깨끗하면 안전하다는 증거인가요?

아니요. 모든 결과에는 검사하지 못한 부분이 나오고, 표준 매핑 현황은 한 분류의 약점 중 규칙이 있는 것이 얼마나 적은지 보여 줍니다. 한계를 참고하세요.

Windows에서도 동작하나요?

네. macOS, Linux, Windows를 지원하며 CI가 세 환경에서 전체 테스트를 실행합니다. Windows에서는 로그인이 자격 증명 관리자에 저장됩니다. 예전 콘솔 창(legacy conhost)과 화면 표시(글꼴, 색, 문자)는 사용자가 직접 확인한 적이 없습니다.

CI에서 쓸 수 있나요?

지금은 어렵습니다. 모든 검사에는 CI 러너에 없는 GitHub 로그인이 필요해서, 러너에서는 차단된 결과만 나옵니다. 로컬에서 PGARD를 실행하고 --format json 또는 --format sarif 출력과 종료 코드(0 완료, 3 차단, 4 부분 완료)를 직접 만든 스크립트에서 사용하세요.

호스팅형 스캐너와 무엇이 다른가요?

코드가 어떤 서비스로도 복사되지 않습니다. 대신 직접 실행해야 하고, 호스팅된 대시보드나 상시 모니터링은 없으며, 검사해도 되는지 GitHub에 확인합니다.

PGARD의 취약점은 어떻게 제보하나요?

공개 이슈가 아니라 비공개로, 저장소 Security 탭의 Report a vulnerability 버튼으로 제보해 주세요. 범위는 보안 정책을 참고하세요. 현상금은 없습니다.
