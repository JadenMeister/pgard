Get started

  1. Build from sourceInstall

    Needs Node.js 22.23.4, 24.22.1 or 26.12.1 (or a newer patch) and Git. The second line puts pgard on your PATH.

    Needs Node.js 22.23.4, 24.22.1 or 26.12.1 (or a newer patch) and Git. Homebrew works too.

    $ git clone https://github.com/JadenMeister/pgard.git && cd pgard && npm ci && npm run build
    $ npm link -w @pgard/cli
    $ npm install -g pgard

  2. Sign in and approve

    Sign in to GitHub once (kept in your OS keychain). The owner installs the PGARD GitHub App; PGARD prints the link if it is missing.

    $ pgard login

  3. Scan

    From your project root. Authorization is checked again; in a terminal, the panel view opens after the text result of a completed or partial scan (not in CI or with PGARD_PANELS=off).

    $ pgard scan

pgard doctor checks your setup; it is not an authorization. Without npm link, run node apps/cli/dist/bin/pgard.js from the clone. Every command and option is in the README.

What it checks

Three areas, picked per scan. Every result says which were fully checked. pgard rules list prints the full catalog.

code

  • SQL injection, XSS, SSRF
  • OS command execution, path traversal
  • Weak or hardcoded cryptography, plaintext passwords
  • Cookie flags, CSRF, no rate limit on login routes

Bounds Current files, uncommitted ones included. Build output and dependencies are skipped and listed.

history

  • Committed .env files
  • Secrets in tracked files
  • Secrets that only exist in history

Bounds Secret values are redacted in every output.

web

  • Security headers, cookie flags
  • CORS with credentials
  • Version disclosure, directory listing
  • Exposed /.env and /.git

Bounds A service on 127.0.0.1 you confirm. Anonymous GET and HEAD; 20 pages, depth 2, 60 s total.

How authorization works

A scanner can also probe other people's code, so every scan, in the CLI and the dashboard, first runs five checks. Only the sign-in is reused and nothing skips them. Missing evidence blocks the scan (exit code 3) and names the failed check.

  1. RepositoryA Git root with one github.com remote.
  2. GitHub identityA one-time sign-in, kept in the OS keychain.
  3. Owner approvalThe owner installed the PGARD GitHub App; for an organization, you are its owner.
  4. Current accessYou have read access right now.
  5. ContributionOwners: history shared with the default branch. Others: a merged pull request or a verified signed commit there.
About the GitHub App

Installing the App on the owner account is the owner's approval, and PGARD can never do it for you. The App ships its public client id; there is no client secret. If the install is all that is missing, PGARD prints the link, waits up to 10 minutes and runs all five checks again from scratch. pgard project verify runs the checks without scanning.

What stays, what leaves

Stays on your machine

  • Source code, Git history and scan results
  • The last 20 results per repository, for 90 days. --no-store opts out
  • Your GitHub sign-in, in the OS keychain, never in a file
  • Reports you export, only where you choose

Goes over the network

  • GitHub: sign-in and authorization metadata, incl. local commit SHAs
  • OSV data, only when you run pgard advisories update
  • Loopback: one GET / per local port
Details

Stored results are owner-only on macOS and Linux. Authorization metadata means identity, App installation, organization membership, access and contributions. The loopback GET happens only after authorization passes. pgard history clear --all deletes stored results. The OSV download is public vulnerability data. The loopback GET shows you what each local port is before you confirm one.

This website is static pages. It does not scan, collect data or offer sign-in or upload, and it is not the dashboard: the dashboard runs on your computer.

Limits

  • coveragePartial coverage is shown; a partial scan exits with code 4.
  • languagesJava and Kotlin: six categories. Python and PHP: two.
  • dependenciesNo known-vulnerability (CVE, OSV) matching yet.
  • remoteOnly a service on 127.0.0.1 you confirm. No logged-in or state-changing requests.
  • signalsPattern based: no findings does not mean secure.
  • accuracySmall corpus (about ten samples per rule), written by the authors.

FAQ

Does my code leave my machine?

No. Code, Git history and results are processed on your computer and not uploaded. The full list of what goes over the network is above.

Why does it need a GitHub sign-in?

To prove you are allowed to scan: your identity, the owner's App installation, your current access and your ownership or contribution. The token is kept in your OS keychain, never in a file.

Which repositories can I scan?

Your own, once the PGARD GitHub App is installed on your account (PGARD guides you through it). Someone else's personal repository only if its owner installed the App and you have current read access plus a merged pull request or a verified signed commit on the default branch. Organization repositories only if you are an active owner of the organization and the App is installed with access to the repository. Remote repositories are never scanned: the target is always the Git root of your current directory.

Is a clean result proof that my project is safe?

No. Every result lists what was not checked, and the standards map shows how few weaknesses in a category have a rule at all. See Limits.

Does it run on Windows?

Yes. macOS, Linux and Windows are supported and CI runs the full test suite on all three. On Windows the sign-in is kept in Credential Manager. The old console window (legacy conhost) and visual rendering have not been verified by a user.

Can I use it in CI?

Not today. Every scan needs a GitHub sign-in that a CI runner does not have, so a runner would produce a blocked result. Run PGARD locally and read --format json or --format sarif and the exit codes (0 completed, 3 blocked, 4 partial) in your own scripts.

More questions

How is it different from a hosted scanner?

Your code is not copied to a service. The trade-offs: you run it yourself, there is no hosted dashboard or continuous monitoring, and it asks GitHub whether you are allowed to scan.

How do I report a vulnerability in PGARD?

Privately, not in a public issue: use Report a vulnerability on the repository's Security tab. The security policy has the scope. There is no bug bounty.
